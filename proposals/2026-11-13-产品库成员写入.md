## 0. 变更摘要（§0.1 规定格式）

```
修改前：
  Products 集合的 create / update / delete 均为 cmsAdminOnly（src/collections/Products.ts:29-34）。
  成员（users，status=active）只能读产品库，新增与改价必须进 /admin 后台，由 CMS 管理员操作。
  AI「日常管理」工具 create_product / update_product 在 handler 开头用 isCmsAdminUser(ctx.user)
  提前拒绝成员，并返回固定文案 PRODUCT_WRITE_DENIED；工具描述也写明「只有 CMS 管理员可以写入产品库」。
  成员即使拥有 catalog:write 能力，也无法通过 AI 或任何成员身份接口新增/修改产品。

修改后：
  产品库的新增与修改放开给所有已启用成员：
  - create: cmsAdminOrMember
  - update: cmsAdminOrMember
  - delete: 保持 cmsAdminOnly（删除产品仍只允许后台 CMS 管理员）
  读权限维持 cmsAdminOrMember 不变（成员原本就能看到售价与成本）。
  AI 工具 create_product / update_product 删除前置的 isCmsAdminUser 硬拦截，
  改由 Products 集合 access + `user` + `overrideAccess:false` 真正裁决；
  readableError 的 403 映射保留，未登录 / 非 active 成员仍会被集合 access 拒绝。
  工具描述与产品库页面说明同步改为「成员可以新增/修改产品与售价；删除产品仍只允许后台管理员」。
  AI_PERMISSIONS 中 catalog:write 不变（已存在，继续作为工具能力声明）。
  不动其它集合权限，不动品牌 / 分类的 cmsAdminOnly。

影响范围：
  权限层：src/collections/Products.ts（create/update）。
  AI 工具层：src/plugins/ai-copilot/tools/admin-handlers.ts（create_product / update_product 前置拦截）、
    src/plugins/ai-copilot/tools/admin-ai.ts（工具描述、不再使用的拒绝文案与判定函数）。
  前端文案：src/app/(frontend)/(workspace)/products/page.tsx 空状态里「新产品在后台添加」的说明。
  业务数据：无字段变更，无迁移。
  下游影响：报价单新增产品项时按产品当前 price 取值（src/lib/services/quote-service.ts），
    成员改价会影响之后新建/刷新报价的行价；已保存的报价行价是快照，不会被历史改价回写。
  审计/运营：产品库目前没有逐字段的修改人与修改时间审计，本变更不新增。

数据迁移 / 兼容：
  无字段、无表结构变更，不需要 migration，不需要数据回填。
  现有产品数据、SKU 唯一约束、分类自动带出 hook、缓存失效 hook 全部保持原样。
  权限变更对存量数据没有影响；回滚只涉及代码。

回滚方式：
  代码回滚即可：把 Products 的 create / update 改回 cmsAdminOnly，
  恢复 create_product / update_product 的 isCmsAdminUser 前置拦截与描述文案。
  无数据需要恢复；若回滚前成员已改过产品，这些改动会保留（属于正常业务数据）。

需要谁批准：
  项目 owner（noone）。属 §0.1「权限模型」变更。
  已获批准：2026-11-13，owner 选择「放开给所有成员」。
```

## 3. 风险

1. **售价 / 成本被普通成员修改**：产品 `price` 是报价单行价的来源（`quote-service.ts` 在新增产品项时读取当前售价），成员误改或恶意改价会直接影响之后生成的报价金额。缓释：报价行价是保存时的快照，历史报价不被回写；如需追责需另加审计（不在本提案范围）。
2. **成本价扩散**：成员原本就能读取 `cost`，本变更不扩大读取面，但写入面扩大后成本数据更容易被改动；成本计算（`src/lib/quote-costs.ts`）会随之为所有成员可见地变化。
3. **误删边界**：删除仍为 `cmsAdminOnly`，成员无法通过 UI 或 AI 删除产品；AI 也没有 delete_product 工具，边界一致。
4. **AI 工具绕过前端**：放开 handler 前置拦截后，真正的权限判断完全依赖集合 access；若未来有人用 `overrideAccess:true` 调 Local API，会绕过限制。现有产品写入路径均显式 `overrideAccess:false`，需要 code review 保持这一约定。
5. **未登录 / 非 active 成员**：仍应被拒绝——`cmsAdminOrMember` 中的 `isMember` 要求 `collection === 'users'` 且 `status === 'active'`；这是本变更后仍需验证的错误路径。

## 4. 验收方式

1. `pnpm exec tsc --noEmit` 通过。
2. `pnpm exec vitest run src/plugins/ai-copilot/tools/admin-ai.test.ts` 通过；用例覆盖成员输入能通过 `normalizeCreateProduct` / `normalizeUpdateProduct`，且不再断言「成员被 CMS 管理员校验拒绝」。
3. `pnpm exec oxfmt --check` 与 `pnpm exec eslint` 对改动文件通过。
4. 代码审查确认：Products 的 `delete` 仍为 `cmsAdminOnly`；两个 AI handler 均保留 `user` + `overrideAccess:false`；`readableError` 仍把中文 403 原样透出。
5. 手工验证（有环境时）：
   - 以 active 成员登录，通过 AI「新增产品」「把某产品改到 399」应成功并写入产品库；
   - 以 active 成员尝试删除产品应被拒绝（后台管理员仍可删）；
   - 未登录或 `status !== 'active'` 的账号调用产品写入应被集合 access 拒绝，返回 403 可读错误；
   - 报价单新增该产品时取到修改后的售价。
